## Causa Tecnica delle Duplicazioni RAG

Il problema alla radice è quasi certamente uno dei seguenti:

|Causa|Sintomo osservato|Fix consigliato|
|---|---|---|
|**Top-K retrieval senza MMR/deduplicazione**|Stesso chunk recuperato più volte con score diverso|Attivare Maximal Marginal Relevance o filtro cosine similarity|
|**Prompt injection ricorrente**|Il paragrafo iniziale si ripete identico N volte|Rimuovere il system prompt dal context injection; usare separatori `<doc_n>`|
|**Chunking overlap eccessivo**|Frasi quasi identiche con piccole varianti|Ridurre overlap dei chunk (es. da 20% a 5%) o usare chunk semantici|
|**LLM context overflow con re-generation**|Il testo inizia daccapo ogni ~400 token|Ridurre il numero di chunk passati o usare modelli con context più lungo|

Dai log del file allegato si vede che il sistema usa retriever sia **dense** che **sparse** — è possibile che entrambi recuperino gli stessi chunk e che questi vengano concatenati senza deduplicazione prima di essere passati al LLM. ## Fix del Sistema RAG – Duplicazioni e Allucinazioni

Il tuo pipeline soffre di **tre problemi sovrapposti**: chunk duplicati in input al LLM, overlap eccessivo tra chunk, e mancanza di deduplicazione tra i risultati dense e sparse. Ecco il fix layer per layer.[](https://www.linkedin.com/posts/amar-tripathi_rag-chunking-embeddings-activity-7424441455282274304-3Fc_)

---

## Layer 1 – Deduplicazione Post-Retrieval (Fix Immediato)

È il fix più rapido: prima di passare i chunk al LLM, si filtrano i duplicati per `chunkindex` e per hash del contenuto. Dal tuo log si vede che lo stesso chunk (es. `chunkindex 984`, `chunkindex 74`) viene restituito sia dal retriever dense che sparse con score diversi — entrambi vanno nel contesto del LLM, causando la ripetizione.[](https://ppl-ai-file-upload.s3.amazonaws.com/web/direct-files/attachments/130566781/8c060791-c94e-4f65-a09a-3461028649f2/tender_fix.md)

python

`from hashlib import sha256 def deduplicate_chunks(retrieved_chunks: list[dict]) -> list[dict]:     """    Deduplication by chunkindex first, then by content hash.    Input: list of dicts with keys 'metadata' (contains 'chunkindex') and 'text'    """    seen_ids = set()    seen_hashes = set()    unique_chunks = []     for chunk in retrieved_chunks:        chunk_id = chunk.get("metadata", {}).get("chunkindex")        content_hash = sha256(chunk.get("text", "").encode()).hexdigest()[:16]         if chunk_id in seen_ids or content_hash in seen_hashes:            continue  # skip duplicate         seen_ids.add(chunk_id)        seen_hashes.add(content_hash)        unique_chunks.append(chunk)     return unique_chunks`

Questo va inserito nel pipeline subito dopo la fusione dei risultati dense+sparse e **prima** della costruzione del prompt.[](https://www.youtube.com/watch?v=F1SgSAnHBGk)

---

## Layer 2 – Reciprocal Rank Fusion con Score Threshold

Invece di concatenare semplicemente dense e sparse, si fondono i ranking con **RRF** e si applica uno score threshold per escludere chunk irrilevanti.[](https://www.mitchellbryson.com/articles/ai-rag-data-quality-at-scale)

python

`def reciprocal_rank_fusion(     dense_results: list[dict],    sparse_results: list[dict],    k: int = 60,    score_threshold: float = 1.5,  # tunable    top_n: int = 8 ) -> list[dict]:     """    Fuses dense and sparse retrieval results using RRF.    Each result dict must have 'metadata.chunkindex' and 'text'.    """    scores = {}    chunk_map = {}     for rank, chunk in enumerate(dense_results):        cid = chunk["metadata"]["chunkindex"]        scores[cid] = scores.get(cid, 0) + 1 / (k + rank + 1)        chunk_map[cid] = chunk     for rank, chunk in enumerate(sparse_results):        cid = chunk["metadata"]["chunkindex"]        scores[cid] = scores.get(cid, 0) + 1 / (k + rank + 1)        chunk_map[cid] = chunk     # Filter by threshold and sort    filtered = {        cid: score for cid, score in scores.items()        if score >= score_threshold / (k * 2)  # normalized    }    ranked = sorted(filtered.items(), key=lambda x: x[1], reverse=True)     return [chunk_map[cid] for cid, _ in ranked[:top_n]]`

---

## Layer 3 – MMR (Maximal Marginal Relevance) per Diversità

Anche dopo RRF, chunk semanticamente quasi identici possono sopravvivere. L'MMR bilancia **rilevanza vs. diversità** escludendo chunk troppo simili tra loro.[](https://www.mitchellbryson.com/articles/ai-rag-data-quality-at-scale)

python

`import numpy as np def maximal_marginal_relevance(     query_embedding: np.ndarray,    chunk_embeddings: list[np.ndarray],    chunks: list[dict],    lambda_param: float = 0.6,   # 0=max diversity, 1=max relevance    top_k: int = 6 ) -> list[dict]:     """    MMR selection from a pre-ranked list of chunks.    """    def cosine(a, b):        return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b) + 1e-9)     selected_indices = []    candidate_indices = list(range(len(chunks)))     while len(selected_indices) < top_k and candidate_indices:        mmr_scores = {}        for i in candidate_indices:            relevance = cosine(query_embedding, chunk_embeddings[i])            if selected_indices:                redundancy = max(                    cosine(chunk_embeddings[i], chunk_embeddings[j])                    for j in selected_indices                )            else:                redundancy = 0            mmr_scores[i] = lambda_param * relevance - (1 - lambda_param) * redundancy         best = max(mmr_scores, key=mmr_scores.get)        selected_indices.append(best)        candidate_indices.remove(best)     return [chunks[i] for i in selected_indices]`

## Layer 4 – Prompt Engineering Anti-Ripetizione

Anche con chunk puliti, il LLM può riciclare il testo del contesto. Aggiungere istruzioni esplicite nel system prompt è fondamentale.[](https://www.linkedin.com/posts/aliasghar-maleki_ai-artificialintelligence-machinelearning-activity-7374850414770307072-CcLW)

python

`SYSTEM_PROMPT = """Sei un assistente esperto in analisi di gare d'appalto. REGOLE OBBLIGATORIE: 1. Rispondi SOLO sulla base dei documenti forniti nel contesto. 2. NON ripetere mai lo stesso concetto o paragrafo più di una volta. 3. Se più chunk del contesto contengono la stessa informazione, citala UNA SOLA VOLTA. 4. Struttura la risposta con sezioni tematiche (non ripetere l'introduzione). 5. Se non trovi un'informazione nel contesto, scrivi esplicitamente "non disponibile nel documento". 6. La risposta deve essere coesa, senza blocchi ripetuti. """ def build_prompt(query: str, chunks: list[dict]) -> str:     context_parts = []    for i, chunk in enumerate(chunks):        doc_id = chunk["metadata"].get("chunkindex", i)        page = chunk["metadata"].get("pagenumber", "?")        context_parts.append(f"[Chunk {doc_id} | p.{page}]\n{chunk['text']}")         context = "\n\n---\n\n".join(context_parts)         return f"""{SYSTEM_PROMPT} <CONTESTO> {context} </CONTESTO> <DOMANDA> {query} </DOMANDA> <RISPOSTA>"""`

## Layer 5 – Riduzione Chunk Overlap nell'Indicizzazione

Il tuo log mostra chunk con overlap alto (chunkindex consecutivi con contenuto sovrapposto). Alla prossima re-indicizzazione:[](https://redis.io/blog/context-window-overflow/)

|Parametro|Valore attuale (stimato)|Valore consigliato|
|---|---|---|
|Chunk size|~500-800 token|512 token|
|Overlap|~20%|5-8% (max 40 token)|
|Splitting strategy|Fixed-size|Semantico (section boundaries)|
|Dedup at ingestion|Assente|SHA-256 hash pre-upsert|

Per il tuo documento (capitolato tecnico strutturato con sezioni numerate), uno splitter **basato su header markdown/numerazione** (`\n\d+\.` come separatore primario) preserva la coerenza semantica meglio del fixed-size.[](https://www.nb-data.com/p/9-chunking-strategis-to-improve-rag)

## Pipeline Completa Integrata

python

`# Pipeline RAG corretta – integrazione di tutti i layer def rag_pipeline(query: str, vector_store, embedder, llm) -> str:     # 1. Retrieve    query_emb = embedder.embed(query)    dense_results  = vector_store.search_dense(query_emb, top_k=15)    sparse_results = vector_store.search_sparse(query, top_k=15)     # 2. Fuse with RRF    fused = reciprocal_rank_fusion(dense_results, sparse_results, top_n=12)     # 3. Deduplicate by ID + hash    deduped = deduplicate_chunks(fused)     # 4. MMR diversification    chunk_embs = [embedder.embed(c["text"]) for c in deduped]    diverse    = maximal_marginal_relevance(query_emb, chunk_embs, deduped, top_k=6)     # 5. Build prompt and generate    prompt = build_prompt(query, diverse)    return llm.generate(prompt, max_tokens=1200)`

Questo riduce il numero di chunk passati al LLM da ~15 a **6 chunk diversificati e deduplicati**, eliminando alla radice la causa delle ripetizioni senza perdita di recall.
